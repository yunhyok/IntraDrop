# IntraDrop

인트라넷(사내망/가정망)으로 연결된 Windows 컴퓨터 사이에서 파일을 간단하게 주고받는 트레이 상주형 프로그램입니다.

![.NET](https://img.shields.io/badge/.NET-8.0%20%7C%20Framework%204.8-blueviolet) ![Windows](https://img.shields.io/badge/Windows-7%20SP1%2B-0078D6) ![License](https://img.shields.io/badge/license-MIT-green)

## 주요 기능

- **트레이 상주**: 평소에는 작업 표시줄 트레이 아이콘으로만 존재합니다.
- **클립보드 전달 (v1.8)**: 텍스트·이미지·파일·폴더를 복사한 뒤 트레이 우클릭 → **클립보드 전달** → 등록된 컴퓨터를 선택합니다. 수신이 완료되면 상대 클립보드에 자동 복사되고 풍선 알림이 표시됩니다. 상대 PC에서 `Ctrl+V`로 붙여넣습니다.
- **컴퓨터 등록**: 상대방 컴퓨터의 IP(또는 호스트명)를 입력해 등록하고, 알아보기 쉬운 **별명**을 붙일 수 있습니다. 목록에서 온라인/오프라인 상태도 보여줍니다.
- **컴퓨터 식별과 별명 보존 (v1.8.2)**: 공유 암호로 확인한 고유 장치 ID와 Windows 컴퓨터 이름을 별도로 저장합니다. 같은 ID의 IP가 바뀌어도 기존 항목과 별명을 유지하며, 새로고침으로 별명이 덮어써지지 않습니다. 목록의 항목 위에 마우스를 올리면 컴퓨터 이름과 장치 ID를 확인할 수 있습니다.
- **그림 도움말**: 트레이 아이콘 우클릭 → **도움말**에서 실제 프로그램 화면으로 외부 컴퓨터 등록, 파일 전송, 설정 방법을 확인할 수 있습니다. 도움말은 인스톨러에 포함되어 오프라인에서도 열립니다.
- **드래그앤드롭 전송**: 트레이 아이콘을 더블클릭 → 컴퓨터 목록에서 대상 선택 → 작은 전송 창에 파일이나 **폴더**를 끌어다 놓으면 바로 전송됩니다. 폴더는 내부 구조 그대로 전송됩니다.
- **탐색기 보내기 메뉴**: 파일/폴더를 선택하고 우클릭 → `보내기` → `IntraDrop - 컴퓨터 이름`을 선택합니다. Windows 11에서는 먼저 `추가 옵션 표시`를 선택합니다. 여러 파일을 한 번에 보낼 수 있습니다.
- **실행 파일도 데이터로 전송**: Windows 기본 보내기 바로 가기를 사용해 다운로드한 설치 파일을 실행하지 않고 전달합니다. 파일의 다운로드 보안 표시는 변경하지 않습니다. 앱 시작/피어 목록 변경 시 메뉴가 갱신되고, 전송 시 최신 대상 주소를 확인합니다.
- **컨텍스트 메뉴 오류 노출**: 대상 미존재, 권한, 전송 실패 등은 MessageBox 대화상자로 즉시 노출됩니다.
- **보내기 전용 설계**: 파일을 보낼 수만 있고, 상대방 컴퓨터의 파일을 가져올 수는 없습니다. 권한/보안 문제를 단순하게 유지합니다.
- **수신 알림**: 상대방이 파일을 보내면 트레이에서 풍선(버블) 알림이 뜨고, 클릭하면 다운로드 폴더가 열립니다.
- **대용량 수락 확인**: 설정한 크기(**256MB / 512MB / 1GB**) 이상의 전송은 받는 쪽에서 **수락**해야만 저장됩니다. 60초 안에 응답이 없으면 자동 거절됩니다. 디스크 여유 공간이 부족하면 자동으로 거절합니다.
- **보안 전송 (선택)**: 설정에서 **공유 암호**를 지정하면 그 이후 전송부터 인증(HMAC)과 AES-256 암호화, 변조 검증이 적용됩니다. 파일을 주고받을 모든 컴퓨터에 동일한 암호를 설정해야 합니다.
- **인증된 UDP 자동 검색 (v1.3)**: 이미 등록해 둔 피어는 같은 서브넷의 인증된 UDP 힌트로 DHCP 주소 변경 후보를 찾고, 암호화된 TCP 신원 확인을 마친 뒤에만 저장된 주소를 갱신합니다. UDP 힌트만으로 목록이 바뀌지는 않습니다.
- **중계 피어 새로고침 (v1.4)**: 직접 연결이 실패하면 새로고침은 공유 암호로 인증된 등록 피어에게 필요한 장치 ID의 최신 후보만 질의한 뒤, 대상 장치와 직접 신원 확인을 완료할 때만 주소를 갱신합니다. 중계 응답은 자동 등록이나 재귀 탐색에 사용되지 않습니다.
- **재시작 시 IP 알림 (v1.7)**: 프로그램 시작·재시작 또는 네트워크 주소 변경 시, 등록된 컴퓨터에 직접 인증 연결을 보내 현재 IP를 알리고 시작 직후 최대 3회 짧게 재시도합니다. 상대는 연결의 실제 IP를 저장하고 열려 있는 목록을 갱신합니다. 같은 공유 암호와 서로 등록·인증된 장치 ID가 필요하며, UDP 자동 검색 설정과 무관하게 동작합니다. UDP 브로드캐스트가 막혀도 상대의 저장 주소로 TCP 연결이 가능하면 동작합니다.
- **허용 목록**: "등록된 컴퓨터에서만 파일 받기"를 켜면 목록에 없는 컴퓨터의 전송 요청을 거부합니다.
- **상호 자동 등록**: 내가 상대방 컴퓨터를 등록하면 상대방의 목록에도 내 컴퓨터가 자동으로 등록되고, 상대방에게는 트레이 알림이 뜹니다.
- **자동 실행**: Windows 시작 시 자동으로 실행됩니다(설정에서 켜고 끌 수 있음).
- **설정 가능 항목**: 다운로드 폴더, 수락 확인 크기, 자동 실행 여부, 내 장치 표시 이름, 통신 포트, 공유 암호, 등록된 컴퓨터에서만 받기 여부.

## 설치

[Releases](https://github.com/yunhyok/IntraDrop/releases)에서 사용하는 Windows 버전에 맞는 인스톨러를 내려받아 실행하고, 파일을 주고받을 **모든 컴퓨터에 각각 설치**합니다. 설치 중 "Windows 시작 시 자동 실행" 옵션을 선택할 수 있습니다.

| Windows 버전 | 인스톨러 | 비고 |
|---|---|---|
| Windows 10 / 11 (64비트) | `IntraDrop-Setup-1.8.2.exe` | .NET 런타임 포함, 별도 설치 불필요 |
| Windows 7 SP1 / 8 / 8.1 (32/64비트) | `IntraDrop-Setup-1.8.2-win7.exe` | [.NET Framework 4.8](https://dotnet.microsoft.com/download/dotnet-framework/net48) 필요 (없으면 설치 시 안내) |

서로 다른 버전의 Windows끼리도 정상적으로 파일을 주고받을 수 있습니다 (동일 프로토콜).

> Windows 7 참고: 모니터별 DPI(배율) 전환은 Windows 10 이상에서만 지원되며, Windows 7에서는 로그인 시점의 시스템 배율을 따릅니다.

### 방화벽 안내

수신과 등록 피어 직접 IP 알림을 위해 TCP 포트(기본 **45671**)가 열려 있어야 합니다. 같은 서브넷 UDP 자동 검색을 사용할 때만 UDP 포트도 허용하세요. 첫 실행 시 Windows 방화벽 허용 창이 뜨면 **개인 네트워크**에 대해 허용해 주세요. VLAN 경계, VPN, Wi-Fi 클라이언트 격리에서는 UDP 자동 검색이 차단될 수 있으므로 수동 등록을 사용하세요. 모든 컴퓨터가 같은 포트를 사용해야 합니다.

## 사용 방법

1. **컴퓨터 등록** — 트레이의 IntraDrop 아이콘을 더블클릭해 컴퓨터 목록을 열고, `추가` 버튼으로 상대방의 IP와 별명을 등록합니다. 암호 없이 등록한 항목은 저장된 주소가 유효할 때 한 번 인증 등록해야 자동 검색을 사용할 수 있습니다. DHCP로 주소가 먼저 바뀌었다면 기존 항목을 `수정`해 현재 IP로 연결하세요.
2. **(선택) 공유 암호 설정** — 트레이 아이콘 우클릭 → `설정`에서 모든 컴퓨터에 동일한 **유효한 공유 암호**를 입력하고 저장하면 그 이후 전송과 자동 검색에 인증·암호화가 적용됩니다. 보호된 암호를 현재 Windows 계정으로 읽을 수 없으면 네트워킹은 안전을 위해 중단됩니다. 암호를 지우거나 바꾸려면 설정의 명시적인 `저장된 암호 지우기` 동작을 사용하세요. 입력란을 비워 둔 채 저장하면 기존 암호가 유지됩니다.
3. **파일 보내기** — 목록에서 컴퓨터를 더블클릭(또는 선택 후 `보내기 창`)하면 작은 드롭 창이 열립니다. 파일/폴더를 끌어다 놓으면 전송됩니다.
4. **탐색기에서 전송** — 파일/폴더를 선택한 뒤 우클릭 → `보내기` → `IntraDrop - 컴퓨터 이름`을 선택합니다. 예: `IntraDrop - Workstation`. 다운로드한 `.exe` 설치 파일도 실행 없이 전송합니다. 이전 버전의 별도 `IntraDrop` 메뉴는 제거됩니다.
5. **파일 받기** — 받은 파일은 설정된 다운로드 폴더(기본: `다운로드\IntraDrop`)에 저장되고 트레이 풍선 알림이 뜹니다. 같은 이름의 파일이 이미 있으면 `이름 (2).확장자` 형식으로 저장됩니다.
6. **설정** — 트레이 아이콘 우클릭 → `설정`에서 다운로드 폴더, 수락 확인 크기(256MB/512MB/1GB), 자동 실행, 포트, 공유 암호, 등록된 컴퓨터에서만 받기 여부를 바꿀 수 있습니다.
7. **도움말** — 트레이 아이콘 우클릭 → `도움말`에서 실제 화면 이미지가 포함된 오프라인 HTML 사용 설명서를 엽니다.

### 기존 컴퓨터가 두 개로 보일 때

암호 없이 등록한 옛 항목에는 인증된 장치 ID가 없습니다. 이후 IP가 바뀐 상태에서 인증 등록되면 옛 항목과 새 항목이 함께 남을 수 있습니다. 기존 별명으로 된 옛 항목을 선택하고 **수정 → 현재 IP 입력 → 동일 컴퓨터 확인**을 진행하면, 해당 IP의 등록된 장치 ID를 직접 인증한 뒤 기존 별명으로 하나의 항목으로 합칩니다. 인증에 실패하거나 목록이 바뀌면 합치지 않습니다.

동일 컴퓨터 판별 기준은 인증된 장치 ID입니다. 컴퓨터 이름은 이름 변경이나 중복이 가능하므로 자동 병합 기준으로 사용하지 않습니다. Windows 컴퓨터 이름 교환은 양쪽 모두 1.8.2 이상일 때 지원하며, 이전 버전과의 인증된 장치 ID 통신은 유지됩니다.

## 클립보드 전달과 Windows 호환성

Windows 7 SP1의 .NET Framework 4.8과 Windows 10/11의 .NET 8에서 공통으로 제공되는 Windows 클립보드 형식을 사용합니다. **양쪽 모두 IntraDrop 1.8.1 이상**이어야 하며, 구버전 상대에게 클립보드 전송을 시도하면 업데이트 안내가 표시됩니다.

| 복사한 내용 | 지원 범위 |
|---|---|
| 텍스트 | 한글·여러 줄·이모지를 포함한 일반 텍스트, UTF-8 기준 1MB까지. HTML/RTF 서식은 일반 텍스트로 전달 |
| 이미지 | Windows 비트맵 클립보드 이미지, PNG로 변환해 16MB 및 2,500만 픽셀까지 |
| 탐색기 파일·폴더 | 실제 파일 내용을 전송하고 받은 PC의 로컬 경로를 클립보드에 등록. 빈 폴더 포함, 파일·폴더 합계 최대 10,000개 |
| 앱 전용 OLE 객체·Outlook 가상 첨부 파일 | 전용 객체 상태는 지원하지 않음. 일반 텍스트/비트맵을 함께 제공하면 해당 형식으로 전달하며, 그 외에는 파일로 저장한 뒤 탐색기에서 복사 |

1. 보낼 텍스트·이미지 또는 파일·폴더를 `Ctrl+C`로 복사합니다.
2. 트레이의 IntraDrop 아이콘 우클릭 → **클립보드 전달** → 목적 컴퓨터를 선택합니다.
3. 받는 PC에서 **클립보드 수신 완료** 알림을 확인하고 원하는 앱이나 탐색기에서 `Ctrl+V`를 누릅니다.

파일은 다운로드 폴더 아래 전송별 폴더에 보관됩니다. 같은 이름의 항목도 구분하며 기존 파일을 덮어쓰지 않습니다. 잘라내기로 복사한 경우도 **복사**로 전달해 송신 원본은 삭제하지 않습니다. 받은 파일은 붙여넣기 전에 삭제하지 마세요. 연결점·심볼릭 링크 등 재분석 지점은 지원하지 않으며 실제 파일·폴더를 선택해야 합니다.

기존 공유 암호·수신 허용 목록·대용량 수락 확인을 적용합니다. 전체 데이터 검증과 수신 클립보드 등록이 모두 끝난 뒤 송신 완료로 표시합니다. 클립보드가 다른 앱에 잠겨 있으면 잠시 재시도하고 실패를 알립니다. 이 경우 이미 받은 파일은 다운로드 폴더에 보존됩니다. Windows 알림 설정에 따라 풍선 표시가 숨겨질 수 있습니다. 공유 암호를 사용하는 클립보드 전송은 송신자가 매번 생성한 난수와 일치하는 인증된 완료 응답을 확인해 이전 완료 응답의 재사용도 거부합니다.

호환성 근거: Microsoft의 [클립보드 형식과 Shell 파일 객체](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard), [Windows Forms 클립보드 데이터 추가](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/advanced/how-to-add-data-to-the-clipboard), [STA·지속 저장·재시도 API](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.clipboard.setdataobject?view=netframework-4.8.1). 임의 객체를 직렬화해 네트워크에서 복원하지 않습니다.

## 동작 방식 (프로토콜 개요)

- 각 컴퓨터의 IntraDrop이 TCP 포트에서 수신 대기합니다.
- 보내는 쪽이 접속해 매직 바이트(`IDRP2`)를 보내면, 받는 쪽은 매번 새로 생성한 난수(nonce)를 응답합니다. 이 nonce는 이후 검증에 포함되어 재전송 공격을 막습니다.
- 이어서 헤더 정보(보낸이, 파일 목록, 총 크기)가 하나의 "세그먼트"로 전송됩니다. 공유 암호가 설정되어 있으면 이 세그먼트는 AES-256으로 암호화되고 HMAC 메시지 인증 코드(MAC)로 서명되며, 받는 쪽은 MAC이 일치해야 세그먼트를 인정합니다. 암호가 없으면 기존처럼 평문으로 오갑니다.
- 받는 쪽은 크기가 임계값 미만이면 자동 수락, 이상이면 사용자에게 수락 여부를 묻습니다. "등록된 컴퓨터에서만 파일 받기"가 켜져 있으면 목록에 없는 상대의 요청은 이 단계에서 거부됩니다.
- 수락되면 파일 데이터도 같은 방식(암호 설정 시 세그먼트 단위 암호화 + MAC)으로 순서대로 스트리밍됩니다. 전체 수신 후 MAC 검증에 실패하면 받은 데이터를 모두 버리고 연결을 종료하며, 성공하면 저장 완료 응답 후 연결이 종료됩니다.
- 수신 경로는 항상 다운로드 폴더 하위로 제한되며(경로 탈출 차단), 전송 중 파일은 `.part`로 저장 후 완료 시 이름이 바뀝니다.
- 온라인 상태 확인(ping)은 매직 바이트 이후 항상 평문으로 오가며, 장치 이름과 버전 정보만 주고받습니다.
- 이전 버전(1.1.0 이하, 매직 `IDRP1`)과는 호환되지 않으므로, 업데이트할 때는 모든 컴퓨터를 함께 올려야 합니다. v1.3에서는 TCP 매직 `IDRP2`를 유지하면서 장치 ID와 인증된 rediscovery를 추가했습니다.

## 보안 참고

- **공유 암호를 설정한 경우**: 모든 전송에 HMAC 기반 인증과 AES-256 암호화가 적용됩니다. 받는 쪽은 변조 검증(MAC)이 통과하기 전까지 파일을 확정 저장하지 않으며, 검증에 실패하면 받은 데이터를 모두 버립니다. 암호는 각 컴퓨터에 DPAPI로 암호화되어 저장됩니다(해당 Windows 계정에서만 복호 가능).
- **암호를 읽을 수 없는 경우**: 보호된 암호 blob이 손상되었거나 다른 Windows 계정에서 만들어졌다면 평문으로 대체하지 않고 전송·등록·자동 검색을 거부합니다. 설정에서 새 암호를 입력하거나 암호 지우기를 명시적으로 선택해야 합니다.
- **공유 암호를 설정하지 않은 경우**: 기존과 동일하게 인증·암호화 없이 평문으로 전송됩니다. 인트라넷(신뢰된 사설망) 사용을 전제로 하며, 공용 네트워크에서는 사용하지 마세요.
- 온라인 상태 확인용 ping(장치 이름 응답)은 공유 암호 설정 여부와 무관하게 항상 인증 없이 동작합니다. 상대방이 켜져 있는지 확인하는 용도일 뿐, 파일을 주고받지는 않습니다.
- "등록된 컴퓨터에서만 파일 받기"를 켜면 목록에 없는 컴퓨터의 전송 요청을 거부할 수 있습니다.
- 받기는 수동적으로만 이루어지며(밀어넣기 전용), 원격에서 내 파일을 읽어갈 수 있는 기능은 없습니다.
