# 클립보드 초기화 점검 (2026-10-16)

기준: v1.10.0 (`55acc94`), 배포 대상: v1.10.1.

## 동작

- 트레이 메뉴의 **클립보드 초기화**를 누르면 현재 PC의 클립보드를 비운다. 완료는 메뉴 상태로, 실패는 메뉴 상태와 수동 작업 실패 알림으로 표시한다.
- 대기 중인 송신과 UI 적용을 기다리던 수신은 취소한다. 초기화 도중 완료된 이전 읽기의 결과도 버린다. 이후 새로 복사하거나 도착하는 내용은 기존 규칙에 따라 처리한다.
- 파일 목록 초기화는 원본 파일을 삭제하거나 이동하지 않는다. 다른 PC의 클립보드, Windows 클립보드 기록(Win+V)을 지우지 않는다. 이미 전송 중인 내용은 회수하지 않는다.
- 기존 Excel 자동 읽기·수신 보호 조건은 유지한다. 명시적으로 누른 초기화에는 자동 수신용 보호 조건을 적용하지 않는다.

현재 클립보드는 Windows Forms의 [Clipboard.Clear](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.clipboard.clear?view=windowsdesktop-10.0)로 비운다. 실패를 성공으로 표시하지 않는다.

## 검증

- 일반 테스트: 90/90 통과.
- 추가한 실제 클립보드 테스트: 3/3 통과. 실제 메뉴 클릭으로 텍스트·이미지·잘라낸 파일 목록 제거, 원본 보존, 대기 읽기 취소, 새 복사 공유 재개를 확인했다. 감시기 유무 두 경우 모두 초기화 전 수신 거부와 초기화 후 새 수신을 확인했다.
- 기존 송신 대기 취소 테스트도 일반 테스트에 포함된다.
- 첫 데스크톱 묶음 실행은 12건 중 10건 통과, 2건 실패했다. `IncomingClipboardCannotReplaceAnUnobservedLocalCopy`는 수신 후 빈 문자열을 읽었고, Excel 복사 시험은 클립보드 소유권 준비 조건에서 실패했다. 이후 분리 실행에서 기존 클립보드 시험과 초기화 시험 4/4, Excel 복사·잘라내기 2/2가 통과했다. 일시적 실패의 원인은 확정하지 않았으며 이를 숨기기 위한 재시도 코드는 추가하지 않았다.
- 실제 클립보드 시험 동안 설치된 IntraDrop을 잠시 종료하고 시험 후 다시 실행했다. 테스트 데이터가 등록된 PC로 자동 공유되지 않게 했다.
- .NET Framework 4.8 Release 빌드: 경고 0, 오류 0. `git diff --check` 통과.
- 독립 코드 검토에서 이전 읽기 호출이 끝나는 동안 들어온 새 복사를 놓칠 수 있는 경로를 확인하고, 초기화 후 클립보드가 다시 바뀌었으면 감시 타이머를 재개하도록 보완했다.

## 확인 범위

실제 Windows 7 장치, OLE 지연 렌더링 중의 중첩 초기화, 타 앱이 계속 클립보드를 잠그는 상황은 직접 재현하지 않았다. Windows 7 빌드와 관련 처리 경로는 빌드·코드 검토로 확인했다. 이번 기능은 사용자가 현재 클립보드를 비우는 동작이며 포인터 이동 원인의 수정으로 주장하지 않는다.
